# 2026-09-24

## starrocks-connector-for-kettle 编译失败排查

**任务**：用户 `mvn` 编译 StarRocks Kettle Connector 报错，要求分析源码是否有误并给出编译流程。

**结论**：Java 源码自洽无编译错误；问题全部在构建配置。

### 根因（已实测复现）
1. 根 POM 父项目 `org.pentaho.di.plugins:pdi-plugins:9.5.0.0-240` 无法解析。
   声明仓库 `https://repo.orl.eng.hitachivantara.com/artifactory/pnt-mvn/` 已下线（NXDOMAIN）。
2. 官方已迁移至 `https://repo.pentaho.com/artifactory/pnt-mvn/`（CNAME → hitachi.jfrog.io），
   **但所有仓库路径返回 401，需要 Basic 认证**（仅 `api/system/ping` 匿名可读）。
3. `starrocks-stream-load-sdk:1.0-SNAPSHOT` 不存在于任何公共仓库；中央仓库只有 `1.0`
   （含 `jar-with-dependencies` 分类器，API 与源码兼容）。
4. `org.eclipse.swt:org.eclipse.swt.gtk.linux.x86_64:4.6` 不在中央仓库（只有 4.3）。

### 已应用的修复（在 D:/starrocks/kettle-src）
- `pom.xml`：2 处仓库 URL → repo.pentaho.com；SWT 4.6 → 4.3；SDK 1.0-SNAPSHOT → 1.0
- `impl/pom.xml`：SDK 1.0-SNAPSHOT → 1.0
- 产出：`D:/starrocks/StarRocks-Kettle-Connector-编译分析与构建指南.md`
- 产出：`D:/starrocks/maven-settings-pentaho-template.xml`

### 源码逻辑缺陷（编译无关，已记录在指南）
最严重一条：`StarRocksKettleConnector.transform()` 用 `r[i]` 而非 `r[data.keynrs[i]]`，
字段映射顺序与上游不一致时会导致导入数据串列。另有 `getProperties()` 自定义 header 值丢失、
`check()` 中 NPE 与 `==` 比较字符串、`@Step.i18nPackageName` 指向错误包等 9 条。

### 环境信息
- 本机只有 JDK 17（`D:\exercise\jdk-17.0.10`），项目要求 JDK 11。
- Maven 由本次分析下载到 `D:/starrocks/tools/apache-maven-3.9.9`（原本未安装）。
