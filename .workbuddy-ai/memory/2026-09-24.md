## starrocks-connector-for-kettle 编译失败排查

**任务**：用户 `mvn` 编译 StarRocks Kettle Connector 报错，要求分析源码是否有误并给出编译流程。

**结论**：Java 源码自洽无编译错误；问题全部在构建配置。

### 根因（已实测复现）
1. 根 POM 父项目 `org.pentaho.di.plugins:pdi-plugins:9.5.0.0-240` 无法解析。
   声明仓库 `https://repo.orl.eng.hitachivantara.com/artifactory/pnt-mvn/` 已下线（NXDOMAIN）。
2. 官方已迁移至 `https://repo.pentaho.com/artifactory/pnt-mvn/`（CNAME → hitachi.jfrog.io），
   **但所有仓库路径返回 401，需要 Basic 认证**（仅 `api/system/ping` 匿名可读）。
3. `starrocks-stream-load-sdk:1.0-SNAPSHOT` 不存在于任何公共仓库；中央仓库只有 `1.0`
   （含 `jar-with-dependencies` 分类器，API 与源码兼容）。
4. `org.eclipse.swt:org.eclipse.swt.gtk.linux.x86_64:4.6` 不在中央仓库（只有 4.3）。

### 已应用的修复（在 D:/starrocks/kettle-src）
- `pom.xml`：2 处仓库 URL → repo.pentaho.com；SWT 4.6 → 4.3；SDK 1.0-SNAPSHOT → 1.0
- `impl/pom.xml`：SDK 1.0-SNAPSHOT → 1.0
- 产出：`D:/starrocks/StarRocks-Kettle-Connector-编译分析与构建指南.md`
- 产出：`D:/starrocks/maven-settings-pentaho-template.xml`

### 源码逻辑缺陷（编译无关，已记录在指南）
最严重一条：`StarRocksKettleConnector.transform()` 用 `r[i]` 而非 `r[data.keynrs[i]]`，
字段映射顺序与上游不一致时会导致导入数据串列。另有 `getProperties()` 自定义 header 值丢失、
`check()` 中 NPE 与 `==` 比较字符串、`@Step.i18nPackageName` 指向错误包等 9 条。

### 环境信息
- 本机只有 JDK 17（`D:\exercise\jdk-17.0.10`），项目要求 JDK 11。
- Maven 由本次分析下载到 `D:/starrocks/tools/apache-maven-3.9.9`（原本未安装）。
- Maven 本地仓库实测为 `C:\Users\tangyin\.m2\repository`（无自定义 settings.xml）。

## 追加：方案 B（离线编译）落地

用户确认方案 A 不可达（拿不到 Pentaho 账号），且本机未装 Kettle、公司电脑上有。

### 关键结论
- 穷举确认：Pentaho 构件在公网**无任何匿名可读来源**（repo.pentaho.com 15 个仓库名全 401；
  中央/阿里/华为/腾讯/JBoss/Atlassian/Mulesoft/RedHat 全部没有；SourceForge 发行包已下架）。
- 唯一路径：从本机已装 Kettle 的 `data-integration/lib` 取 jar。

### 已交付（`D:/starrocks/kettle-offline/`）
- `PdiOfflineSetup.java` —— 单文件工具（`java Xxx.java` 直接跑，JDK11+）。扫描 lib/*.jar，
  从 jar 内嵌 `META-INF/maven/*/*/pom.properties` 读真实坐标，按仓库布局写入本地仓库；
  生成聚合依赖 `pentaho-kettle:pdi-kettle-all`（type=pom）和占位父 POM `pdi-plugins`。
- `1-setup-repo.sh` / `2-build.sh` —— 两步封装脚本。
- `方案B-离线编译流程.md` —— 完整文档。

### 项目 POM 改造（kettle-src）
- 移除 pentaho 两个仓库声明（注释保留原文）
- impl/ui 各加一条 `pentaho-kettle:pdi-kettle-all`（type=pom, scope=provided）
- impl 移除 kettle-core/kettle-engine 的 `tests` classifier 依赖（离线拿不到）
- assemblies/plugin 显式声明 maven-assembly-plugin（appendAssemblyId=false）
- 占位父 POM 用 `maven.compiler.release=11` 锁死字节码版本

### 已实测验证
- 手工按仓库布局写入的构件可被 Maven 解析（含 `-o` 离线模式），无需 `_remote.repositories`
- `<type>pom</type>` + `provided` 能传递解析且子依赖继承 provided（kettle jar 不会进插件包）
- `release=11` + JDK17 → major version 55（Java 11 字节码）
- 用合成假 lib 跑通全流程：父 POM 解析 → 依赖解析 → 进入 javac
- JDK17 可读 SWT 4.3 / JFace 3.3（2007）老 jar
- 未验证：真实 kettle jar 的完整编译与 assembly 打 zip（本地拿不到 PDI 安装包）

### 待办 / 风险
- 用户需确认公司 Kettle 版本；若 ≠ 9.5.0.0-240，要同步改 `<pdi.version>` 和 `<parent><version>`
- 编译必须带 `-Dmaven.test.skip=true`
