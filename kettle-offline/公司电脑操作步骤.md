# 公司电脑操作步骤（Git Bash）

> 本文件随仓库同步，在公司电脑上 `git pull` 后照着做即可。

## 0. 前提

| 项 | 值 |
|---|---|
| Maven 本地仓库 | `D:\Maven\apache-maven-3.9.11\repo`（脚本会自动探测，不用手填） |
| 要用的 JDK | `C:\Program Files\Java\jdk-11`（**不要用 JDK 8**） |
| Kettle 版本 | `8.3.0.0-371`（项目 pom 已按它对齐） |

你机器上 `JAVA_HOME` 指向 `jdk1.8.0_101`，而 `2-build.sh` 会继承它 —— **必须先显式覆盖**：

```bash
export JDK_HOME="C:/Program Files/Java/jdk-11"
"C:/Program Files/Java/jdk-11/bin/java.exe" -version   # 应显示 11.x
```

为什么不能用 JDK 8：

1. `1-setup-repo.sh` 用 `java PdiOfflineSetup.java` **单文件源码运行**，需要 JDK 11+（JEP 330）。
2. `PdiOfflineSetup.java` 里用了 `String.isBlank()`，也是 JDK 11 才有的 API。

## 1. 拉取代码

```bash
cd /d/starrocks/starrocks-connect-kettle
git pull
ls kettle-src/pom.xml          # 应该存在了（以前这里因坏子模块是空的）
```

## 2. 灌 Maven 本地仓库

```bash
cd kettle-offline
bash 1-setup-repo.sh "D:/starrocks/pid-lib" 8.3.0.0-371
```

注意：

- 路径**一定要加引号**。不加引号时 bash 会把 `\s`、`\p` 当转义吃掉，
  `D:\starrocks\pid-lib` 会变成 `D:starrockspid-lib`。
- 版本参数必须和 `kettle-src/pom.xml` 里的 `<pdi.version>` 一致，都是 `8.3.0.0-371`。
- 这一步会生成占位父 POM，其 `maven.compiler.release` 按版本自动取 **8**（PDI 8.x 跑在 Java 8 上）。

## 3. 编译打包

```bash
bash 2-build.sh
```

产物：`kettle-src/assemblies/plugin/target/*.zip`

## 4. 报错对照表

| 报错 | 原因 | 处理 |
|---|---|---|
| `找不到 java: ...` | 在 **cmd** 里敲了 `bash`，命中的可能是 WSL 的 bash（不认 `C:\...` 路径） | 一律用 **Git Bash**（提示符是 `MINGW64`），别在 cmd 里跑 |
| `Could not find artifact pentaho-kettle:pdi-kettle-all:pom:9.5.0.0-240` | pom 的 `<pdi.version>` 与灌入仓库的版本不一致 | `<pdi.version>` 和 `<parent><version>` 都改成 `8.3.0.0-371` |
| `invalid flag: --release` / `release version 11 not supported` | Maven 实际跑在 JDK 8 上 | `export JDK_HOME="C:/Program Files/Java/jdk-11"` 后重跑 |
| `在 .../kettle-src 下找不到 pom.xml` | `kettle-src` 为空（坏子模块导致） | `git pull` 拉到修复后的提交 |

## 5. 为什么以前 `kettle-src` 是空的

本地 `kettle-src` 里带着自己的 `.git`（是从上游 clone 来的），被 `git add` 记成了
**mode 160000 的 gitlink（子模块指针）**，但仓库里**没有 `.gitmodules`** —— 这就是个坏子模块。

后果：GitHub 上图标异常、点不开；`git clone` / `git pull` 只会建一个**空目录**。

已修复：删掉嵌套 `.git`，`git rm --cached kettle-src` → `git add kettle-src`，
现在 `kettle-src` 是普通目录（`040000 tree`），57 个文件正常入库。

> 以后往仓库里放"另一个 git 仓库"时，必须先删掉它的 `.git`，否则会重蹈覆辙。
